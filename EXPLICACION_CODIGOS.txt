def guardar_mensaje(nombre, contenido):
    """Guarda el mensaje en MySQL y MongoDB"""
    try:
        # Guardar en MySQL
        cursor.execute('SELECT id FROM usuarios WHERE nombre = %s', (nombre,))
        usuario = cursor.fetchone()
        
        if usuario:
            id_usuario = usuario[0]
            cursor.execute(
                'INSERT INTO mensajes (id_usuario, contenido) VALUES (%s, %s)',
                (id_usuario, f'{nombre}: {contenido}')
            )
            db_mysql.commit()

Explicación:
1. Busca el ID del usuario en MySQL
2. Si existe, inserta el mensaje en la tabla mensajes
3. db_mysql.commit() confirma la transacción

        # Guardar en MongoDB
        db_mongo.usuarios.update_one(
            {'nombre': nombre},
            {'$push': {'mensajes': {'contenido': contenido, 'fecha': datetime.now()}}}
        )

Explicación:
1. Busca el usuario por su nombre
2. {'$push': ...} agrega un mensaje a la lista 'mensajes'
3. El mensaje incluye contenido y timestamp

    except Exception as e:
        print(f'Error al guardar mensaje: {e}')

Captura cualquier error durante el proceso

SECCIÓN 5: CREAR Y EJECUTAR SERVIDOR
═════════════════════════════════════

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
server.bind((HOST, PORT))
server.listen(5)

- socket.AF_INET: IPv4
- socket.SOCK_STREAM: TCP (no UDP)
- SO_REUSEADDR: Permite reutilizar el puerto rápidamente
- bind(): Asigna el HOST y PORT
- listen(5): Puede tener 5 conexiones en espera


print(f'Servidor multiusuario escuchando en {HOST}:{PORT}...')

try:
    while True:
        conn, addr = server.accept()
        # Crear hilo para cada cliente
        t = threading.Thread(target=manejar_cliente, args=(conn, addr))
        t.daemon = True
        t.start()

- Acepta conexiones infinitamente
- Para cada conexión, crea un nuevo hilo
- daemon=True: El hilo se cierra cuando finaliza el programa

SECCIÓN 2: FUNCIÓN recibir_mensajes()
══════════════════════════════════════

def recibir_mensajes(client):
    """Hilo para recibir mensajes del servidor de forma continua"""
    while True:
        try:
            data = client.recv(1024).decode()
            if data:
                print(f'\n{data}')
                print('Tu: ', end='', flush=True)
            else:
                break
        except:
            break

¿Por qué necesitamos un hilo separado?
- El programa principal envía mensajes (espera input del usuario)
- Este hilo recibe mensajes constantemente
- Sin el hilo, no podría recibir mientras espera input

end='': No añade salto de línea después del prompt
flush=True: Asegura que el prompt aparezca inmediatamente

═══════════════════════════════════════════════════════════════════════════
                      DIFERENCIA MySQL vs MongoDB
═══════════════════════════════════════════════════════════════════════════

MYSQL (SQL - Relacional):
  Tabla usuarios:
  ┌─────┬────────┬─────────────────┐
  │ id  │ nombre │ email           │
  ├─────┼────────┼─────────────────┤
  │  1  │ Alex   │ alex@email.com  │
  │  2  │ Juan   │ juan@email.com  │
  └─────┴────────┴─────────────────┘
  
  Tabla mensajes:
  ┌─────┬────────────┬───────────┬──────────────┐
  │ id  │ id_usuario │ contenido │ fecha_envio  │
  ├─────┼────────────┼───────────┼──────────────┤
  │  1  │     1      │ Hola      │ 2026-05-...  │
  │  2  │     2      │ Qué tal   │ 2026-05-...  │
  │  3  │     1      │ Bien      │ 2026-05-...  │
  └─────┴────────────┴───────────┴──────────────┘


MONGODB (NoSQL - Documental):
  Documentos en colección 'usuarios':
  {
    "_id": ObjectId("..."),
    "nombre": "Alex",
    "email": "alex@email.com",
    "mensajes": [
      { "contenido": "Hola", "fecha": ISODate("2026-05-...") },
      { "contenido": "Bien", "fecha": ISODate("2026-05-...") }
    ]
  }
  
  {
    "_id": ObjectId("..."),
    "nombre": "Juan",
    "email": "juan@email.com",
    "mensajes": [
      { "contenido": "Qué tal", "fecha": ISODate("2026-05-...") }
    ]
  }


VENTAJAS DE CADA UNA:

MySQL:
  ✓ Estructura fija y predecible
  ✓ Buen para datos relacionados
  ✓ Fácil de consultar con JOIN
  ✓ Mejor para transacciones complejas

MongoDB:
  ✓ Flexible: cada documento puede ser diferente
  ✓ Excelente para datos anidados
  ✓ Más rápido para consultas que no necesitan JOIN
  ✓ Escala mejor horizontalmente

═══════════════════════════════════════════════════════════════════════════
                        CONCEPTOS CLAVE
═══════════════════════════════════════════════════════════════════════════

SOCKET TCP/IP:
  - Conexión orientada a la conexión
  - Garantiza entrega de datos en orden
  - Puerto 5000 es donde escucha el servidor

THREADING:
  - Permite múltiples clientes simultáneamente
  - Cada cliente corre en su propio hilo
  - Sin threading, solo podría atender a 1 cliente a la vez

TRANSACCIONES:
  - db_mysql.commit(): Confirma cambios en MySQL
  - Sin commit(), los cambios no se guardan

ÍNDICES:
  - email VARCHAR(100) UNIQUE: No permite duplicados
  - PRIMARY KEY: Identifica unícamente cada fila
